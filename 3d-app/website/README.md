# 3DEEZI website and API

A Laravel 12 backend and React 19 / TypeScript website for the sportswear design flow. The website follows the existing mobile app: choose a creation method, select a sport and garment, customise a live 3D kit, save projects and versions, manage artwork, and export a design. The Laravel JSON API is also available to the mobile apps.

This is a separate application in `website/`. Existing Flutter source and its bundled Three.js renderer remain unchanged. `npm run sync-assets` copies the mobile project's artwork, fonts and viewer into the website's public media directory. Mobile API integration is documented in [docs/API.md](docs/API.md); the existing Flutter screens do not automatically call this new backend.

## Run locally

Requirements: PHP 8.2 or newer with Laravel's required extensions and the appropriate PDO driver, Composer, and Node.js with npm. SQLite is the default development database. XAMPP's PHP executable can be used if `php` is not on your PATH.

From the repository root:

```sh
cd website
composer install
npm install
```

For a new checkout, copy `.env.example` to `.env` once. In PowerShell:

```powershell
Copy-Item -LiteralPath .env.example -Destination .env
```

Set `APP_URL=http://127.0.0.1:8000` in `.env`, keep `DB_CONNECTION=sqlite`, then run:

```sh
php artisan key:generate
php -r "file_exists('database/database.sqlite') || touch('database/database.sqlite');"
php artisan migrate
npm run sync-assets
npm run build
php artisan serve --host=127.0.0.1 --port=8000
```

Open **http://127.0.0.1:8000** and create an account through the website. Do not overwrite an existing `.env` or regenerate an existing application key during normal restarts.

For frontend development, run `npm run dev` in another terminal alongside `php artisan serve`. Stop the Vite development server and build the frontend before serving the built site. If a stale `public/hot` file remains after a terminated Vite process, remove that file so Laravel uses the built manifest.

The 3D studio requires a browser with WebGL support. Its renderer and fonts are bundled locally; no external 3D service is needed. Export captures are generated from the live garment scene.

## XAMPP / Apache

The preferred virtual-host document root is `D:/xampp/htdocs/3d-app/website/public`. Enable Apache rewrite support and allow the shipped `.htaccess` rules. Only Laravel's `public` directory should be directly web accessible.

For a local subfolder preview, use **http://localhost/3d-app/website/public** and set the same URL as `APP_URL`. The website reads Laravel's base URL for frontend routes, API calls and media. Keep the `website/.htaccess` access rules in place to prevent direct access to configuration and application files outside `public`. Run `php artisan config:clear` after editing environment settings. Apache and command-line PHP both need the selected database driver.

## MySQL

Create an empty MySQL database and replace the SQLite settings in `.env`:

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=3deezi
DB_USERNAME=your_database_user
DB_PASSWORD=your_database_password
```

Remove an explicit SQLite `DB_DATABASE` path if present, then run `php artisan config:clear` and `php artisan migrate`. These commands create the schema in MySQL; they do not transfer existing SQLite accounts or projects.

## Implementation and scope

- `resources/js/` contains the React website; `resources/js/components/KitViewer.tsx` embeds the mobile app's bundled Three.js viewer and provides live design updates and PNG capture.
- `routes/api.php` defines the versioned mobile/web endpoints. Controllers and validation live under `app/Http/`; project, version, account and asset data are stored through Laravel models.
- `public/media/` is generated by `npm run sync-assets`. Run it again when source artwork or the mobile viewer changes.
- `docs/API.md` describes authentication, project persistence, uploads, concepts and exports, with request examples.

AI runs on the server through OpenAI (`app/Services/OpenAiDesigner.php`) when `OPENAI_API_KEY` is set in `.env` (models: `OPENAI_TEXT_MODEL`, default `gpt-6-luna`; `OPENAI_IMAGE_MODEL`, default `gpt-image-2`). The key is never sent to the browser.

- `POST /api/v1/concepts`: four concept designs from the brief (uploaded references are analysed), each with a quick AI preview render.
- `POST /api/v1/ai/pattern`: a seamless print pattern for the chosen concept, applied to the live 3D kit.
- `POST /api/v1/ai/showcase`: a photoreal marketing image made from a capture of the live 3D kit (scenes: stadium tunnel, studio podium, on athlete, locker room), saved to the user's Assets.

Without a key, concepts fall back to the local procedural provider and the Showcase button is hidden. Tests always use a faked OpenAI (`phpunit.xml` clears the key).

PNG mockups and design specifications are design previews. Production cut patterns, graded manufacturing files, vector tech packs, manufacturing approval workflows, purchasing, and fulfilment are not generated by this implementation. Social sign-in and email delivery require their own provider integrations. This work does not publish or deploy a public website.

## Checks

```sh
php artisan test
npm run build
```

The PHP feature suite covers the API's important persistence and access-control behavior. The frontend build includes TypeScript checking. An end-to-end browser review should include account creation, project save/reopen, asset upload, live colour and text changes, front/back capture, and a narrow mobile viewport.
